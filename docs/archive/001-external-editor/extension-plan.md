# 外部编辑器扩展计划书

计划日期：2026-08-03
依据：[`investigation-report.md`](investigation-report.md)

## 目标

在不改变现有剪贴板常驻工作流的前提下，让 ScratchEditor 能作为 Codex、pi-coding-agent 和
Claude Code 的同步外部提示词编辑器。完成后，以下命令应构成稳定的公共接口：

```text
ScratchEditor.exe [--wait] <file>
```

只要提供文件位置参数，程序就进入瞬态文件模式；`--wait` 作为便于环境变量表达和用户理解的
显式选项保留。调用进程本身持续运行到编辑完成，因此不需要额外的后台守护程序或完成文件。

主程序本身不静默修改用户的 `VISUAL`、`EDITOR`、Codex 配置或 pi 配置。需要持久配置时由用户显式运行
[`scripts/configure-codex-editor.ps1`](../../scripts/configure-codex-editor.ps1)；脚本会将产物部署到并列的
Codex/pi 与 AHK 用户级稳定目录，写入 Windows 用户级 `VISUAL`/`EDITOR`，维护 pi 设置、AHK 回退路径
和 Git Bash `~/.bashrc` 中的同名变量。标准 `scripts/build.ps1` 每次成功构建后都会自动执行此同步。
CLI 级自动化使用临时配置目录，并在 `/quit` 返回后清理。

## 不变约束

- 不带文件参数时，现有 `--background`、`--toggle`、`--show` 和 `--hide` 行为保持不变。
- 现有 AHK、固定生产管道名称和剪贴板异常保护保持不变。
- 文件模式不读取或修改系统剪贴板。
- 文件模式不连接或占用现有生产 IPC 管道。
- 不引入 Qt WebEngine、浏览器内核、MCP、LSP 或插件系统。

## 设计方案

### 1. 命令行模式判定

在 [`src/main.cpp`](../../src/main.cpp) 中声明 `--wait` 和一个可选位置参数 `file`，并在创建
控制器之前完成互斥校验：

- 无文件参数：进入现有 `ClipboardResident` 模式。
- 恰好一个文件参数：进入 `ExternalFile` 模式。
- 多个文件、空路径，或者文件模式与 `background/toggle/show/hide` 混用：输出错误并返回
  非零退出码。

文件模式应把相对路径基于启动工作目录转换为绝对路径，但不要求文件位于项目目录内，因为
三种 CLI 通常在系统临时目录创建文件。

### 2. 文件会话对象

新增一个小型 C++ 文件会话对象，例如 `ExternalFileSession`，集中负责：

- 保存规范化后的绝对路径；
- 读取文件并把 UTF-8 解码为 `QString`；
- 使用 `QSaveFile` 或等价安全写入方式保存 `QString::toUtf8()`；
- 保存最后错误和脏状态；
- 明确区分空文本与未加载状态。

该对象不负责窗口、动画、IPC 或命令注册，便于对文件往返行为做无 GUI 单元测试。

### 3. 控制器数据源分流

为 [`EditorController`](../../src/editorcontroller.h) 增加明确的会话模式和可选文件会话：

- `showEditor()` 在常驻模式继续读取剪贴板，在文件模式加载文件会话的初始文本。
- `commitAndHide()` 保持现有常驻实现；文件模式使用单独的 `commitAndExit()`，避免把文件
  错误混进 `clipboardHealthy` 状态。
- 文件模式保存成功后结束应用事件循环；失败时显示错误、恢复焦点并保持窗口可见。
- 文件模式不执行隐藏动画终态，以免调用方在窗口不可见后仍等待动画或常驻进程。

不要把外部文件命令暴露到现有生产 IPC。瞬态进程本身就是 CLI 所等待的完成句柄。

### 4. 关闭与保存语义

在 [`qml/Main.qml`](../../qml/Main.qml) 中由控制器暴露只读的 `externalFileMode` 属性，并保持
统一的 QML 入口：窗口关闭和 Escape 仍调用控制器，但控制器根据模式决定行为。

文件模式采用与现有草稿窗一致的“关闭即提交”语义：

1. `Ctrl+S` 只保存，窗口继续打开。
2. Escape 或窗口关闭先执行最终保存。
3. 保存成功：退出码 `0`，结束进程。
4. 保存失败：取消关闭，保留编辑内容并显示可操作错误。

第一版不必增加独立的“放弃并退出”UI。若后续需要取消，可新增明确命令并返回非零退出码，
不能把取消伪装为成功保存。

### 5. 退出码与诊断

公共约定只要求 `0` 表示成功、非零表示失败。实现时应至少区分以下错误类别，并把简短诊断
写入标准错误或用户可见状态：

- 命令行参数无效；
- 文件不存在、不是普通文件或不可读；
- UTF-8 解码策略拒绝输入；
- 临时保存或最终替换失败；
- QML 加载失败。

不要在文件模式启动成功后提前返回 `0`。pi 明确只在子进程退出码为 `0` 时读取编辑结果。

### 6. 编码与文本完整性

三种 CLI 的提示词临时文件按 UTF-8 文本处理。实现和测试应固定以下规则：

- 写出 UTF-8，不主动添加 BOM。
- 不把空文本替换为旧内容。
- 保留 Unicode、CJK、emoji 和嵌入的 NUL 之外的普通文本。
- 验证首尾空白、末尾换行和多行内容往返；不主动追加末尾换行。
- 对 CRLF 输入明确测试 Qt 文本文档的规范化结果，并在文档中说明最终策略。

如果要求字节级保留原始换行风格，应在文件会话中记录首次读取的换行约定；否则第一版可以
统一为 `\n`，但必须由验收测试固定，不能依赖未记录的 Qt 隐式行为。

- 文件模式绕过单实例服务器、命令转发、剪贴板和隐藏常驻行为。

完成标准：启动进程在窗口打开期间保持运行，关闭成功后退出 `0`，保存失败时不退出。

### 阶段 C：自动化回归

- 新增独立测试入口，使用临时目录和带空格、CJK 的路径。
- 覆盖常驻实例已经运行时再启动文件模式的场景。
- 并行启动至少两个不同文件会话，确认互不覆盖。
- 回归现有 Stage 2、编辑行为、窗口界面与性能测试，确认剪贴板模式未变化。

完成标准：新旧测试同时通过，生产 IPC 管道仍只有一个常驻所有者。

### 阶段 D：真实 CLI 验收与文档

在原生 Windows 中分别验证：

```powershell
$env:VISUAL = "$env:LOCALAPPDATA\ScratchEditor\CodexEditor\ScratchEditor.exe --wait"
$env:EDITOR = $env:VISUAL
```

pi 可额外验证用户设置：

```json
{
  "externalEditor": "C:\\Users\\<用户名>\\AppData\\Local\\ScratchEditor\\CodexEditor\\ScratchEditor.exe --wait"
}
```

依次在 Codex、pi-coding-agent 和 Claude Code 中输入已有多行文本、按 `Ctrl+G`、修改、清空、
保存和关闭，确认 composer 精确接收结果。当前 Codex 与 pi 的真实流程已通过自动化；Claude
Code 暂缓。随后可补充 WSL 路径转换包装示例，但不把 WSL 逻辑编入 Windows GUI 主程序。

完成标准：Codex 与 pi 的原生 Windows 验收通过；待用户恢复 Claude Code 范围后补齐第三项。
README 已包含会话级配置、行为和测试入口。

## 验收矩阵

| 场景 | 预期结果 |
|---|---|
| 空 composer 打开后输入文本 | 关闭后 CLI 获得新文本 |
| 已有多行文本 | 内容完整加载，修改后完整返回 |
| 清空全部内容 | 临时文件被写为空，CLI composer 变空 |
| CJK、emoji、引号和反斜杠 | UTF-8 往返无损 |
| 路径包含空格和中文 | 正常打开、保存和退出 |
| 常驻剪贴板实例已运行 | 文件模式仍为独立进程，不转发给常驻实例 |
| 两个文件模式并发 | 各自只修改自己的文件 |
| 文件只读或保存时被锁定 | 窗口不退出，显示错误，退出码不伪报成功 |
| 冷启动文件模式 | 编辑期间子进程持续存在，关闭后退出 `0` |
| 无文件参数启动 | 原剪贴板常驻行为完全不变 |

## 风险与控制

- **误入单实例路径**：在 `main.cpp` 最早阶段决定模式，文件模式不得调用
  `forwardToExistingInstance()` 或 `startServer()`。
- **关闭事件递归**：QML 继续拒绝原始关闭事件，由控制器保存后显式退出，避免重复触发。
- **保存失败导致文本丢失**：失败时不隐藏、不退出、不清空编辑文档。
- **空文本被忽略**：文件写入不复用当前剪贴板模式的 `!text.isEmpty()` 条件。
- **命令路径含空格**：项目自身正确解析位置参数；部署文档分别给出 PowerShell、pi JSON 和
  WSL 包装示例。
- **历史性能退化**：文件核心只在显式文件模式构造，常驻热唤醒路径不增加磁盘访问。
