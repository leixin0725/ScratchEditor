## 收录与维护

- **模块文档**面向修改该模块的人。记录职责边界、必须保持的行为、非显然的设计约束或可复现的操作步骤。行为改变时同步更新。每项事实只在所属模块维护，跨模块用链接指向原文。
- **当前工作**放入 `work/<topic>.md`。只收录需要跨次交接的调查、待决策事项和实施约束，标明状态。结案时先将持续有效的结论并入模块，再将有追溯价值的材料归档，移除当前工作入口。
- **历史归档**使用 `archive/YYYY-MM-DD-<topic>/`。同一专题合放计划、调查和验收，保留功能编号和原文件名。日期优先取结案或验收日，其次取报告日期，最后取 Git 首次归档该专题的提交日期。归档后冻结正文。
- **追查历史**先用 `git log -- <代码路径>` 定位时间、主题或提交，再查[对应日期的归档](archive/)和[验收基线](../artifacts/baselines/README.md)。只归档能补充提交历史的根因、决策、复现步骤和证据。
- **索引**随入口、路径或工作状态变化更新。普通变更由 Git 记录。写入前先确定读者需要做哪个判断，删去重复功能清单、流水账和逐行代码复述。
