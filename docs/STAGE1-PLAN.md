# 迁移执行计划与阶段 1 验收门

## 保护边界

- 原始 `dev-links/AutoHotkey/KeysRedirect.ahk` 只读，迁移期间继续作为回退版本。
- 新 Qt 工程、AHK 测试桥、工具链、构建和测试结果全部位于本工作区。
- 不引入 Qt WebEngine、WebView 或浏览器内核。
- 阶段 1 默认使用 Qt Quick `basic` 渲染循环；目标机对照实测表明它能避免大文本输入时
  的线程交接抖动，同时保持 GPU 场景图、60 FPS 动画和 0% 空闲 CPU。
- 阶段 1 未通过性能与输入验收前，不进入阶段 2。

## 现有行为基线

- 默认窗口 920×640，最小 500×320；无标题栏、置顶、可从四边/四角缩放。
- Microsoft YaHei UI、纯文本、多行、自动换行、Tab 输入。
- 首次和每次重新显示都从剪贴板载入文本。
- 隐藏时仅当编辑文本非空才回写剪贴板，窗口与进程保持复用。
- 当前 AHK 快捷键为 `ScrollLock`。

## 分阶段计划

1. 阶段 0：冻结旧 AHK UI，记录上述兼容基线并保持原文件不变。
2. 阶段 1：实现最小 Qt Quick 垂直原型和 AHK 本地 IPC；构建后逐项实测第 7.2 节。
3. 阶段 2：仅在阶段 1 全部达标后补齐深色主题细节、状态记忆、智能滚动条、
   Escape、异常处理以及正式回退开关。
4. 阶段 3：功能对等稳定后实现 Markdown 高亮、编辑命令、搜索、命令面板、
   按需预览和快捷键配置。
5. 阶段 4：按实际需要实现设置、主题/字体和轻量过渡；历史、标签页等保持可选。
6. 阶段 5：只有在功能对等且稳定使用验证完成后，才移除旧 AHK GUI；快捷键、
   IPC 和启动失败回退仍保留。

## 阶段 1 自动验收证据

| 能力/指标 | 验证方式 | 验收门 |
|---|---|---|
| 冷启动至 IPC/QML 可输入 | 部署冒烟后，以全新进程启动到 `ready=true`，5 次 | 每次 ≤300 ms |
| 常驻热唤出 | 命名管道请求到首帧交换，40 次 | 外部 P95 ≤50 ms |
| 输入到画面 | `SendInput` Unicode 键事件覆盖完整刷新相位，60 次 | 内部 P95 ≤16.667 ms |
| 空闲 CPU | 无轮询定时器，5 秒 CPU 时间差 | 归一化 CPU ≤0.5% |
| 空闲工作集 | 常驻隐藏进程 Working Set | ≤80 MB |
| 轻量动画 | 1 秒 `XAnimator` 探针 | ≥55 FPS 且 P95 帧 ≤20 ms |
| 10 万字符 | 载入、选择、滚动、再输入 | 选择/滚动与输入无跨帧阻塞 |
| 中文输入法 | `QInputMethodEvent` + 系统 Microsoft Pinyin 键盘输入 | 组合态和“你好”提交均成功 |
| CJK/高 DPI | 字形查询、窗口 DPR/尺寸/标志状态 | CJK 字形存在、DPR>0、标志匹配 |
| 无白闪 | 隐藏预创建、首帧中心像素采样 | 首帧为编辑区暗色底色 |

测试会在目标机已安装的 Microsoft Pinyin 中用普通虚拟键输入 `nihao` 并选择候选，
随后恢复测试前的输入法切换状态；合成输入法事件只作为组合态的补充覆盖。
